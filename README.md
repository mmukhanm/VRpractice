# Практическая работа № 6 — Автомастерская

**Андижан Мухаммед · вариант 4 · Unity 6000.6.0f1 / URP 17.6 / XRI 2.6.5**

Проект создан по заданию «Импорт 3D-моделей, настройка пространственного звука». В нём реализованы автомобиль с включаемым двигателем, компрессор, захватываемые гаечные ключи, стол, кресло, лампа, переносное радио, анимированный вентилятор и движущийся дрон для проверки Доплера.

## Работа по профилированию: этапы 1–6

Добавлена сборка сцены **Profiling_Андижан** на основе Variant_Андижан: World Space FrameTimeMeter, CP1/CP2/CP3, нагрузка 0–2000 объектов, отдельные SRP/Instancing/LOD, точный BadBehaviour и GoodBehaviour с ProfilerMarker, 300 физических тел, восемь источников света и режим Baked после настоящего запекания. Команда **VR Practice → Profiling → Create or rebuild scene** создаёт сцену; **Validate scene** проверяет структуру. Первый полный Build workshop scenes также создаёт её, если она отсутствует. Пересборка профилировочной сцены сохраняет резервную копию существующей под Artifacts/SceneBackups.

В Play: **1/2/3** — контрольные точки, **N** — число объектов, **0** — N=0, **M** — оптимизация, **B/G/V** — плохой/хороший/без скрипта, **P/O** — падение Convex/Box, **L** — освещение, **F9** — 300 кадров, **Backspace** — исходная сцена. Результаты идут в `Application.persistentDataPath/Profiling/<сессия>`; табличка показывает путь. Движение блокируется на время записи; положение HMD продолжает отслеживаться.

- [Порядок выполнения всех шести этапов](Docs/profiling.md), включая Deep Profile, Profile Analyzer, Frame Debugger и Windows Development Build.
- [Excel-шаблон с графиком и бюджетом 13,9 мс](Docs/Profiling_Template.xlsx) — **без вымышленных замеров**.
- `python3 Tools/analyze_profiling.py --input <папка_обычных_CSV> --output Artifacts/Profiling_Report.xlsx` заполняет таблицы и график реальными записями. Нужен `pip install -r Tools/profiling-requirements.txt`.

Облачные проверки не заменяют Unity: реальные .data, CPU/GPU/GC, Top 5, снимки экрана, запекание и сборка Windows здесь не получены из-за отсутствия Unity Editor. Runtime-код и команды редактора подготовлены, но ещё не проверены запуском.

## Открыть и запустить

**Исправление ошибок Unity 6000.6:** проект содержит локальный пакет `Packages/com.unity.xr.interaction.toolkit` — XRI 2.6.5 с исправлением устаревших деревьев XR Debugger. При обновлении копируйте и эту папку. [Инструкция при CS0619 и ошибке CameraCheckpoints](Docs/unity-upgrade.md#исправление-cs0619-и-cameracheckpoints) объясняет обновление существующего проекта без правок кэша.

1. Клонируйте репозиторий и откройте его корень через Unity Hub в **Unity 6000.6.0f1**. Используйте обычный checkout: отдельный Git worktree не нужен.
2. Дождитесь установки закреплённых пакетов и компиляции. Нужен доступ к `packages.unity.com` и `download.packages.unity.com`.
3. `WorkshopBuilder` при первом открытии создаст URP, импортирует образцы входных действий XRI, настроит анимацию и соберёт две сцены. Если сборка не произошла, выполните **VR Practice → Build workshop scenes**. Не запускайте пересборку поверх несохранённых изменений сцены без их сохранения.
4. Выполните **VR Practice → Validate scenes**, откройте `Assets/Scenes/Variant_Андижан.unity` и нажмите **Play**.
5. Подключите наушники. Для общего задания есть сцена `Import_Audio_Андижан.unity`.

Сцены и URP-материалы собираются редактором из исходных ресурсов; `Assets/Generated` содержит восстанавливаемые результаты и не хранится в Git. После клонирования сцены появляются при сборке редактором. Это не готовый исполняемый файл и не подтверждённая сборка для VR-шлема.

## Управление

| Действие | Клавиатура и мышь |
|---|---|
| Перемещение | WASD |
| Поворот головы | Удерживать правую кнопку мыши |
| Взять / отпустить предмет | Навести перекрестие, E, расстояние до 3 м |
| Бросить предмет | Q |
| Радио, двигатель, компрессор | F; радио также включается в руке |
| Меню с тремя ползунками микшера | Esc |
| Скрыть / показать эталонный куб | F1 |
| Переключить на настоящий XR Device Simulator | F2 |

В XR Device Simulator используются оригинальные карты управления XRI 2.6.5. Tab переключает выбранное устройство; левый Shift / Space выбирают левый / правый контроллер; G управляет grip, левая кнопка мыши — trigger. Точные назначения показаны в `Assets/Generated/XR Device Simulator/*.inputactions` и документации пакета. **Grip выбирает/захватывает объект, trigger активирует выбранный объект.** Главное меню открывается кнопкой primary (A/X) контроллера; доступно и Esc. Ползунки в мировом Canvas управляются лучом контроллера или мышью.

Физический шлем необязателен для работы. Для него дополнительно выберите **OpenXR** в Project Settings → XR Plug-in Management для нужной платформы и профиль ваших контроллеров. Сборка на Meta Quest/другой шлем здесь не выполнялась.

## Переход на Unity 6000.6.0f1

Версия редактора закреплена в ProjectSettings/ProjectVersion.txt, URP — 17.6.0, uGUI — 2.6.0. Обновлены Input System, glTFast, XR Management, OpenXR и Test Framework. XRI обновлён до 2.6.5: текущие XR-скрипты используют API 2.x; переход на XRI 3.x требует отдельной переделки взаимодействий.

Если вы уже открывали старую версию проекта, сохраните свои сцены и резервную копию перед открытием в новом редакторе. После обновления выполните **VR Practice → Build workshop scenes** и **Validate scenes**. Старый маркер SetupComplete больше не считается проверкой новой версии: редактор подскажет пересборку, сохраняя существующие сцены до явного запуска команды. Чтобы получить свежие samples вместо старых локальных копий, переместите `Assets/Generated` вместе с `Assets/Generated.meta` в резервную папку **вне Assets** перед открытием редактора, затем соберите сцены. Не удаляйте пользовательские изменения.

Для загрузки пакетов нужен также `cdn.packages.unity.com`: официальный сервер пакетов перенаправляет на него загрузки. Подробности перехода и источники версий — [Docs/unity-upgrade.md](Docs/unity-upgrade.md). Фактический импорт, компиляция и Play Mode в Unity 6000.6.0f1 ещё не проверены в этой облачной среде.

## Что реализовано

- FBX: стол, радио, автомобиль, ключ, вентилятор; OBJ: кресло и LOD1; GLB: лампа, компрессор, дрон. Геометрия экспортирована в метрах; корни размещённых моделей имеют масштаб 1 и нулевой корректирующий поворот.
- Стол — BoxCollider, кресло — упрощённый выпуклый MeshCollider, захватываемые предметы — Rigidbody + XRGrabInteractable + звук захвата/отпускания и удара.
- Вентилятор: механическая Generic-анимация, импортированный циклический FBX-клип и Animator Controller.
- Кресло: 39 936 треугольников в исходном OBJ, 19 966 в LOD1, кубический заменитель LOD2. Порог culling `.026` соответствует примерно 30 м при текущем FOV и размере; точное расстояние зависит от камеры и проверяется в Unity.
- Текстуры кресла ≤ 1024 px, нормали импортируются как Normal Map, неподвижное окружение — Static. Вращающийся вентилятор и захватываемые объекты не помечены статичными.
- MainMixer: Music, SFX, Ambient; три exposed-параметра, сохранение PlayerPrefs; снимки Normal/Paused. Дополнительные родительские SFXDuck/AmbientDuck приглушаются на 18 dB, поэтому snapshots не конфликтуют с exposed-громкостью ползунков. Меню останавливает физику и анимацию, аудио продолжает демонстрировать приглушение.
- 2D-музыка — Streaming; радио — 3D Logarithmic, 1/10 м; вентилятор — Custom, ноль на 4 м, Spread 90°; дрон — круг 5 м, 9 м/с, Doppler 1. Скорость источника обновляется физикой.
- Комната с четырьмя стенами, проходом и потолком, AudioReverbZone Room. Радио остаётся источником на самом захватываемом объекте.
- Вариант 4: двигатель и компрессор по активации, три захватываемых ключа, три варианта удара со случайной высотой и громкостью по скорости.

HRTF-спатиализатор не включён: используются штатное стереопанорамирование, затухание, Доплер и реверберация Unity. По условию HRTF проверяется, если плагин установлен; стандартный 3D-звук не доказывает различимость «спереди/сзади».

## Проверки и отчёт

В облачной среде прошли проверки целостности ресурсов и повторный импорт всех моделей Blender с проверкой размеров и стыка анимации. **Unity Editor отсутствует**, поэтому компиляция Unity, Play Mode, сцены, EditMode-тесты, Stats, VR-управление и проверка в наушниках здесь не выполнены. Их нельзя считать пройденными по проверкам Blender или C#-синтаксиса.

```bash
python3 Tools/validate_assets.py
blender -b --python-exit-code 1 --python Tools/validate_models.py -- "$PWD"
```

В машине с установленным и активированным Unity:

```bash
# UNITY_EDITOR — путь к локальному Unity 6000.6.0f1; секреты в Git не добавлять.
"$UNITY_EDITOR" -batchmode -nographics -projectPath "$PWD" \
  -executeMethod VRPractice.Editor.WorkshopBuilder.Build -quit -logFile /tmp/vrpractice-build.log
"$UNITY_EDITOR" -batchmode -nographics -projectPath "$PWD" \
  -executeMethod VRPractice.Editor.WorkshopBuilder.ValidateScenes -quit -logFile /tmp/vrpractice-validation.log
"$UNITY_EDITOR" -batchmode -nographics -projectPath "$PWD" \
  -runTests -testPlatform EditMode -testResults /tmp/vrpractice-tests.xml -logFile /tmp/vrpractice-tests.log
```

Не добавляйте `-quit` к `-runTests`: дождитесь завершения Test Runner и проверьте свежий XML с выполненными тестами, а не только код выхода. Команды Unity подготовлены, но в этой среде не запускались.

- [Отчёт Word](Docs/Report_Андижан_Мухаммед.docx): теория, таблица моделей, описание реализации, места для измерений/скриншотов/видео, листинги скриптов.
- [Проверка и сценарий видео](Docs/acceptance.md): что нужно продемонстрировать преподавателю.
- [Объяснение скриптов](Docs/script-guide.md): материалы для построчного разбора на защите.

Отчёт является черновиком: группа не указана, реальные Stats и слуховые наблюдения нужно внести после запуска. Видео со звуком и скриншоты Unity не созданы в отсутствие редактора. Модели, кроме лицензированного кресла, и все звуки созданы процедурно; требование задания самостоятельно **найти/скачать** три модели и звуки покрыто не полностью. При строгом требовании внешних источников замените нужные оригинальные ресурсы на проверенные CC0/CC-BY и обновите CREDITS; их лицензии не выдуманы.

## Пересоздание ресурсов и сдача

Исходные FBX/OBJ/GLB и WAV уже находятся в Git; Blender не нужен для обычного открытия Unity. Только для сознательной регенерации:

```bash
blender -b --python-exit-code 1 --python Tools/generate_models.py -- "$PWD"
python3 Tools/generate_audio.py
python3 Tools/generate_mixer.py
```

Эти команды перезаписывают авторские ресурсы; не запускайте их поверх собственных изменений без сохранения. Перед сдачей сначала соберите и проверьте сцены в Unity, закройте редактор, затем выполните:

```bash
python3 Tools/package_project.py
```

Архив для сдачи сохраняется в `Artifacts/VRpractice_Андижан.zip` вместе с локально собранными сценами и Generated; Library, Temp, Logs, .git, персональные настройки и архивы исключаются. Источники распространяются по MIT, оригинальные модели и аудио — CC0; зависимости сохраняют свои лицензии.
